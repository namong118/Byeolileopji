# 보고서 틀

`<...>` 는 채우고, 해당 없는 절은 "없음" 으로 남긴다 (절을 지우지 않는다 — 다음 보고서와 비교하기 쉽게).

```markdown
# 모델·엔진 업데이트 확인 — <YYYY-MM-DD>

- 가져오기 도구: parallel-search `web_fetch`
- 확인한 페이지: <N>개 (성공 <N>, 실패 <N>)
- 실행 구분: <첫 실행 — 페이지별 최근 3개를 기준 항목으로 보고 | 이전 확인일 이후 새 항목>
- 영향 표기: **있음** (별일없지에 바로 영향) / **없음** / **확인 필요** (페이지만으로 판단할 수 없음)

## 요약

| 페이지 | 새 항목 | 있음 | 확인 필요 | 가져오기 |
| --- | --- | --- | --- | --- |
| <이름> | <N> | <N> | <N> | 성공 / 실패 |

## ⚠ 강조: 사용 중인 모델의 변경·지원 종료

<gemini-3.5-flash-lite, gemini-embedding-2 의 지원 중단·종료·변경 공지. 날짜, 내용, 원문 링크, 영향.
없으면 "해당 공지 없음 (가져온 범위: <가장 오래된 날짜> ~ <가장 최신 날짜>)">

## 페이지별 새 항목

### <이름>

<!-- 일반 페이지 -->

- **영향**
  - <날짜/버전>: **<있음|없음|확인 필요>** — <이유>

<!-- Ultralytics 는 아래 형식 -->
- 고정 버전: `<requirements.txt 의 버전>` → 이후 나온 버전 <N>개 (<가져온 범위 기준. 고정 버전이 범위 밖이면 "N개 이상">)
- 따로 볼 항목 (YOLO26 / 학습·export(NCNN, ONNX) / 호환성 깨짐)

| 날짜 | 버전 | 구분 | 요약 | 원문 | 영향 |

- 나머지 패치: `<버전>`, `<버전>`, ...
```
